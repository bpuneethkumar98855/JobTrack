# Application status timeline

Status history timestamps are generated by the backend with `Instant.now()` and represent UTC instants. The history entity converts those instants to UTC wall-clock values for MySQL `DATETIME(6)`, because that MySQL type does not carry a timezone. The API returns ISO-8601 timestamps with a trailing `Z` (for example, `2026-10-09T09:45:00Z`). The details page formats those timestamps in the browser's local timezone for display.

`applicationDate` remains a separate calendar date (`LocalDate`) and is never used as a status-event timestamp.

The status-history table must be created manually from the verified migration SQL. Hibernate remains configured with `spring.jpa.hibernate.ddl-auto=validate`; it will validate the table after it exists but will not create or alter it.
